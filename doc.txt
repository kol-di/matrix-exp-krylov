
ЗАДАЧА (контекст для Cursor):
Нужно реализовать действие матричной экспоненты y = exp(t·A)·v на нескольких CUDA‑GPU через подпространство Крылова (Arnoldi для общего A; опционально Lanczos для SPD). В реализации применяем cuSPARSE/cuBLAS и NCCL. Без NVSHMEM и без communication-avoiding (s-step) техник. Матрица A хранится в CSR и заранее разбиается по строкам между GPU. Термин “ghost” — это элементы текущего вектора, которые необходимы устройству для столбцов A, принадлежащих другим устройствам. Всё, что можно, держим в памяти устройств; CPU используется для «малой экспоненты» exp(t·H_m)·e1 и для координации. Цель — получить корректный, воспроизводимый и масштабируемый прототип, который даёт точный результат и показывает перекрытие вычислений и обменов.

КЛЮЧЕВАЯ ИДЕЯ АЛГОРИТМА:
Мы не строим полную exp(A), а считаем её действие на вектор через Крылов: строим ортонормированный базис V_m ≈ span{v, A v, …, A^{m-1} v} (Arnoldi), получаем малую проекцию H_m (верхне‑хессенбергова), вычисляем w = exp(t·H_m)·e1 на CPU (m — десятки/сотни), и возвращаемся в исходное пространство: y ≈ ||v|| · V_m · w. Качество решения оценивается по невязке, и при необходимости делаем рестарт (берём y как новый стартовый вектор и повторяем процесс). На нескольких GPU каждая итерация сводится к локальному SpMV + векторной линалгебре, обменам ghost и глобальным редукциям (AllReduce).

ДАННЫЕ И ПАМЯТЬ:
• Формат A: CSR. Разбиение 1D по строкам на p устройств: A = [A^(0); A^(1); …; A^(p-1)].  
• Для каждой карты g: CSR локальных строк, разбиение по столбцам на on‑diag (колонки, чьи владельцы — g) и off‑diag (колонки с владельцами ≠ g). Строим карты owner→consumer и компактные списки ghost индексов.  
• Векторы: локальные сегменты q_k^(g), w^(g), y^(g) на девайсах. Ghost‑буферы (двойная буферизация) для q_j.  
• Всё device‑resident: в ходе итераций CPU↔GPU передачи не делаем (кроме крошечных скаляров H_m при желании), финальный y копируем на хост только по запросу.  
• Подготовка: включить peer access между локальными устройствами, использовать cudaMemcpyPeerAsync для p2p. Редукции — через NCCL AllReduce.

ПОСЛЕДОВАТЕЛЬНОСТЬ ВЫЧИСЛЕНИЙ (TOP→DOWN, строго по времени; колонка = “где выполняется”):
CPU → подготовка:
1) Разбить A по строкам, сформировать owner/ghost карты; разбить v по тем же индексам.  
2) На каждой GPU: cudaMalloc буферы (CSR, базис V_m, рабочие векторы), создать cuBLAS/cuSPARSE handles и дескрипторы (cusparseCreateCsr, cusparseCreateDnVec).  
3) Инициализировать NCCL коммуникатор(ы) для выбранных девайсов. Включить cudaDeviceEnablePeerAccess между локальными GPU. Создать три стрима на каждую GPU: stream_compute (SpMV/BLAS), stream_comm (копии ghost), stream_reduce (AllReduce).

GPU+Collectives → нормировка стартового вектора и получение q1:
4) На каждой GPU: локально cublasNrm2(||v_local||).  
5) NCCL AllReduce(SUMSQ) по квадратам норм → глобальная ||v||.  
6) На каждой GPU: cublasScal(v_local/||v||) → q1.  
С этого момента поддерживаем пер‑GPU колонку для GPU‑операций и отдельную для NCCL‑операций; порядок строго сверху вниз.

ЦИКЛ АРНОЛЬДИ (j = 1..m):
A) Подготовить q_j:  
   • В stream_comm: собрать ghost компоненты q_j через cudaMemcpyPeerAsync по картам owner→consumer (двойная буферизация).  
   • В stream_compute: параллельно запустить on‑diag SpMV. Синхронизировать off‑diag этап через cudaEventRecord/StreamWaitEvent.

B) Построение w = A·q_j (на каждой GPU):  
   • cusparseSpMV(A_on * q_j) в stream_compute.  
   • Дождаться ghost, затем cusparseSpMV(A_off * q_j_ghost) и cublasAxpy к w для накопления.

C) Ортогонализация MGS (+ реортогонализация при нужде):  
   • Для i = 1..j: локально s_i = cublasDot(q_i, w).  
   • NCCL AllReduce(SUM) по s_i → h_{i,j}.  
   • Локально cublasAxpy(w -= h_{i,j} q_i).  
   • (Опционально повторить вторым проходом MGS для устойчивости: повторить dot/reduce/axpy только при обнаруженной потере ортогональности.)

D) Нормировка нового вектора и добавление q_{j+1}:  
   • Локально s2 = ||w_local||^2 (cublasNrm2 → квадрат).  
   • NCCL AllReduce(SUMSQ) → ||w||.  
   • На каждой GPU: cublasScal(w/||w||) → q_{j+1}.  
   • Сохранить скаляры текущей колонки H: h_{1..j,j} и h_{j+1,j}. (Хранить H_m можно на хосте или на одной «координаторной» GPU; объём мал.)

ПОСЛЕ m ШАГОВ:
E) На CPU: собрать H_m и посчитать «малую экспоненту» wH = exp(t·H_m)·e1 (через Eigen/LAPACK).  
F) На каждой GPU: подъём результата в исходное пространство — y_local = V_m * wH (удобно как сумма AXPY по столбцам V_m или один cublasGemv по локальной матрице Q^(g) ∈ R^{n_g×m}).  
G) Оценка невязки (residual-based) и решение о рестарте: базовая оценка ||r_m|| ≈ |h_{m+1,m}|·||e_m^T exp(t·H_m)·e1||. Если ≤ tol — завершаем; иначе делаем рестарт: v := y и повторяем цикл построения Крылова ещё на m шагов (с накоплением результата).  
H) По завершении: при необходимости D2H копия y на хост для вывода/верификации.

ВЫЗОВЫ ФУНКЦИЙ И ПЕРЕДАЧИ ДАННЫХ (минимальный набор):
• Разреженное умножение: cusparseCreateCsr, cusparseCreateDnVec, cusparseSpMV_bufferSize, cusparseSpMV (CSR, OP_N).  
• BLAS‑1: cublasNrm2, cublasDdot/SDot, cublasDaxpy/SAxpy, cublasDscal/SScal.  
• Коллективные редукции: ncclCommInitRank, ncclAllReduce(buf, buf, count, ncclDouble, ncclSum, comm, stream_reduce). Группируй близкие редукции с ncclGroupStart/End.  
• Меж‑GPU копии: cudaDeviceEnablePeerAccess, cudaMemcpyPeerAsync(dstDev, srcDev, size, stream_comm).  
• Стримы и события: cudaStreamCreate, cudaEventRecord, cudaStreamWaitEvent — для перекрытия copy/compute.  
• Хост/девайс: cudaMalloc/Free, cudaMallocHost (пиннутая память для ускорения H2D/D2H), cudaMemcpyAsync (для первичной загрузки CSR и v).

ГЛАВНЫЕ КЛАССЫ/МЕТОДЫ, КОТОРЫЕ НУЖНО БУДЕТ РЕАЛИЗОВАТЬ:
1) CSRHost — хранение CSR на хосте и сервисные функции:  
   • from_matrix_market / from_binary (чтение),  
   • partition_rows(num_gpus) → std::vector<CSRHost>,  
   • build_owner_ghost_maps(parts) → структуры для ghost (списки индексов, маршруты p2p).

2) DeviceContext (на каждую GPU):  
   • Поля: device_id; три стрима; cuBLAS/cuSPARSE handles; дескрипторы SpMat/DnVec; указатели на device‑буферы (CSR, q_k, w, y, ghost‑буферы); рабочие скаляры (на девайсе) для AllReduce.  
   • Методы: init_handles(); create_streams(); alloc_from(CSRHost part); create_descriptors(); destroy().

3) NcclContext:  
   • init_all(dev_ids);  
   • allreduce_sum(double* dptr, size_t count, stream_reduce);  
   • allreduce_sumsq(double* dptr, size_t count, stream_reduce) — это тот же SUM над квадратами (можно предварительно возвести в квадрат локально и редуцировать один скаляр).

4) ArnoldiParams: m (длина подпространства до рестарта), t, tol, max_restarts, reorthogonalize.  

5) ArnoldiRunner: высокоуровневый оркестратор:  
   • compute_expmv(v_host, y_host): полная процедура (нормировка q1 → несколько рестартов Крылова → возврат y_host).  
   • Внутренние методы (каждый шаг с чёткими границами):  
     – init_q1();  
     – ghost_exchange_qj(j) — p2p сбор ghost q_j;  
     – spmv_on_off(j) — два cusparseSpMV (on‑diag, затем off‑diag после ghost) + AXPY;  
     – orthogonalize_mgs(j) — цикл i=1..j: dot → AllReduce → axpy (реортог — по флагу/критерию);  
     – normalize_new_vector(j) — nrm2 → AllReduce → scal;  
     – store_H_column(j) — скопировать h_{*,j}, h_{j+1,j} на хост/координатор;  
     – small_expm_and_lift() — вызвать CPU‑функцию exp(t·H_m)·e1 и выполнить подъём V_m*wH на GPU;  
     – residual_estimate() и restart_if_needed().

ВНЕОЧЕВИДНЫЕ ДЕТАЛИ И ВАЖНЫЕ ПРАВИЛА:
• Перекрытие copy/compute: всегда делить SpMV на on‑diag и off‑diag; запустить on‑diag сразу, а ghost копировать параллельно в stream_comm и синхронизировать событием перед off‑diag. Двойная буферизация ghost избегает «пузырей» между итерациями.  
• Память и формат: CSR — универсально; держать V_m столбцами (SoA) для быстрой линейной комбинации при подъёме (AXPY‑петля или Gemv). Хост‑буферы для I/O — pinned.  
• Редукции — узкое место на большом числе GPU: группируй несколько скаляров в один AllReduce (ncclGroupStart/End). В первоначальном прототипе достаточно одной редукции на dot и одной на норму.  
• Ортогональность: используем MGS с реортогонализацией. Проверять потерю ортогональности по величине добавки/внутренним продуктам; при падении ортогональности выполнять второй проход.  
• Числовая стабильность: двойная точность предпочтительна для устойчивости ортогонализации и оценки невязки.  
• Рестарт: используем residual‑based оценку через h_{m+1,m} и «малую экспоненту». При рестарте устанавливаем v := y, не обнуляем пер‑GPU контекст (переиспользуем буферы/дескрипторы).  
• Ошибки и диагностика: оборачивать CUDA/cuBLAS/cuSPARSE/NCCL вызовы макросами проверки; логировать время SpMV, dot, AllReduce, ghost‑копий; печатать норму невязки по шагам.  
• Масштабирование: сначала одноузловый запуск (NVLink/NVSwitch/P2P). На многоузловой конфигурации заменить P2P на CUDA‑aware MPI пересылки для ghost (или позже NVSHMEM).  
• Тестируемость: начать с диагональных/маленьких матриц (сравнение с CPU эталоном: y = (t·A).exp()·v). Сходимость улучшается при росте m и/или числе рестартов; tol контролирует остановку.  
• Безопасность ресурсов: корректно освобождать дескрипторы/handles/streams и device‑память на каждой GPU, а также разрушать NCCL коммуникаторы.

КОНЕЧНАЯ ЦЕЛЬ:
Cursor должен по этому описанию реализовать: (а) загрузку/разбиение CSR, (б) multi‑GPU Arnoldi с MGS, (в) NCCL‑редукции и p2p ghost копии, (г) CPU‑малую экспоненту и подъём результата, (д) рестарт по невязке, (е) минимальные sanity‑тесты на маленьких матрицах. Все названия операций, вызовов библиотек и шаги передачи данных перечислены выше — следовать им буквально.
